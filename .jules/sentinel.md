## 2025-03-03 - Command Injection via JSON.stringify
**Vulnerability:** Command injection in `computer.exec()` and `exec()` calls where user input was escaped using `JSON.stringify()` instead of proper shell escaping. `JSON.stringify()` creates a string bounded by double quotes (e.g., `"user_input"`). In bash, double-quoted strings are subject to variable expansion and command substitution, meaning an input like `$(touch pwned)` or `\`touch pwned\`` would execute the command instead of treating it as a literal string.
**Learning:** `JSON.stringify` does not provide safe shell escaping. It escapes double quotes (as `\"`), but it leaves characters like `$`, `\``, and `\` unescaped within double quotes, which bash interprets.
**Prevention:** When passing user inputs or dynamically generated strings to shell commands evaluated by `bash` (like `bash -lc` used inside `computer.exec`), always use single quotes (`'`) for bounding and replace any existing single quotes in the input with `'\\''` (closing the current single quote, inserting a literal single quote, and reopening). For example: `'${userInput.replace(/'/g, "'\\''")}'`.
